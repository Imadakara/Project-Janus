# llm-bench

Изолированный тестовый стенд для проверки локальных LLM (3-4B, CPU-only, ~8 ГБ RAM) как
кандидатов на Слой 3 (генеративный слой) диалогового движка Project Janus — см. корневой
`CLAUDE.md`, раздел «Dialogue engine architecture». Задача Слоя 3 узкая: получить несколько
фрагментов данных + инструкцию по тону и ответить в роли, опираясь только на переданные
фрагменты. Стенд проверяет именно это, а не общие способности модели.

**Изолирован от основного приложения** — ничего не импортирует из `@/lib`, `@/app`, не влияет
на сборку сайта. Не тянет новых зависимостей: обычный `fetch` к локальному эндпоинту Ollama.

## Что здесь

- `prompt-template.ts` — сборка системного промпта: роль/тон персонажа (параметром) + блок
  фрагментов данных (в явных разделителях) + жёсткие правила + few-shot примеры.
- `fixtures.ts` — три тестовых кейса (`BENCH_CASES`), каждый = фрагменты + вопрос + описание
  ожидаемого поведения для ручной оценки.
- `run-bench.ts` — прогон всех кейсов против модели в Ollama, по 3 попытки на кейс.

Весь текст фрагментов и few-shot примеров — черновой, в стиле сеттинга, помечен
`TODO: заменить финальным текстом от нарративного дизайнера`. Для проверки поведения модели
это не важно — важна структура (роль/тон, разделители фрагментов, жёсткие правила), она
совпадает с боевым промптом (`lib/ai/prompt-builder.ts`, `lib/ai/system-prompt.ts`).

## Как запустить

1. Поставить [Ollama](https://ollama.com) и скачать модель-кандидата:
   ```
   ollama pull qwen3:4b
   ```
   Для сравнения — второго кандидата, например не-thinking `qwen2.5:3b` (см. "Известные
   грабли" ниже, почему thinking-режим qwen3 не всегда сравним напрямую):
   ```
   ollama pull qwen2.5:3b
   ```
2. Убедиться, что Ollama слушает (обычно поднимается сама как служба; если нет — `ollama serve`
   в отдельном терминале).
3. Прогнать стенд (из корня репозитория, без установки новых пакетов — `tsx` уже есть в
   `devDependencies`):
   ```
   npx tsx experiments/llm-bench/run-bench.ts qwen3:4b
   npx tsx experiments/llm-bench/run-bench.ts qwen2.5:3b
   ```
   Без аргумента модель по умолчанию — `qwen3:4b`. Эндпоинт по умолчанию —
   `http://localhost:11434/v1`, переопределяется переменной окружения `OLLAMA_BASE_URL`.
   Лимит длины ответа (`MAX_TOKENS`, по умолчанию 300) — переменной `MAX_TOKENS` (см. раздел
   "Известные грабли" ниже — thinking-моделям вроде qwen3 может понадобиться больше).

Если Ollama не запущена или модель не скачана — скрипт печатает понятную ошибку с точной
командой (`ollama serve` / `ollama pull <модель>`), а не сырой fetch-эксепшен.

Вывод на каждую попытку: кейс, номер попытки, вопрос, ответ, время генерации в мс. В конце —
сводка: среднее время ответа и токены/сек (если Ollama вернула `usage.completion_tokens` —
не все версии/режимы это отдают, тогда сводка честно пишет «н/д»).

## Известные грабли

**qwen3:4b по умолчанию — thinking-модель.** Ollama гоняет её с включённым рассуждением:
видимый ответ уходит в `message.content`, а скрытая цепочка рассуждений — в отдельное поле
`message.reasoning`, но `usage.completion_tokens` считает то и другое вместе. На нашем системном
промпте (роль + жёсткие правила + фрагменты + few-shot, ~700-900 токенов) рассуждение регулярно
съедает весь `MAX_TOKENS` до того, как модель успевает начать видимый ответ — на прогоне
(`npx tsx run-bench.ts qwen3:4b` с MAX_TOKENS по умолчанию 300) все 9 попыток вернули пустой
`content` за 58-213 секунд каждая. `run-bench.ts` теперь такие случаи различает явно: если
`content` пуст и `finish_reason === "length"`, в вывод добавляется строка с длиной ушедшего в
reasoning текста и подсказкой поднять лимит.

Что делать:

- Поднять бюджет через `MAX_TOKENS=1200 npx tsx experiments/llm-bench/run-bench.ts qwen3:4b`
  (или больше) — но даже 1500 токенов не гарантируют завершение за разумное время: в ручной
  проверке рассуждение на CPU не уложилось в 1500 токенов / 180 секунд на том же промпте.
  На CPU-инстансе thinking-режим qwen3:4b может оказаться непригоден для чат-задержки
  Слоя 3 в принципе — это тоже результат сравнения, а не только баг стенда.
- Взять не-thinking модель того же класса — например, `qwen2.5:3b` (проверено вручную:
  тот же системный промпт, MAX_TOKENS=300, корректный ответ по CASE_1 без выдуманных фактов
  за ~54 секунды на CPU).
- Эндпоинт `/v1/chat/completions` (OpenAI-совместимый, требование ТЗ) параметр `think: false`
  не поддерживает — он игнорируется, рассуждение всё равно происходит (проверено вручную). Отключить
  thinking-режим для qwen3 через этот эндпоинт нельзя; это ограничение Ollama, не стенда.

## Как добавить новый кейс

В `fixtures.ts` добавить объект `BenchCase` (id, title, fragments, question,
expectedBehavior) и включить его в массив `BENCH_CASES` — `run-bench.ts` подхватит
автоматически, ничего в раннере менять не нужно.
